## 設計の中心

利用者の端末で、多言語の入力・認識・翻訳・編集・出力を組み合わせる。UI、処理エンジン、モデル、OS接続は能力契約で分離する。推論用モデルは利用者が許諾を確認して別途導入し、配布するコードは許諾型の依存方針に従って審査する。

UIの共通基盤はFlutter、処理との接続はC ABIとローカルIPCを採る。Linuxの埋込みホストは依存方針に合わせた実装・検証対象として設計する。

## 資料の扱い

JSON Schemaは構造、検査スクリプトは構造間の整合、Cヘッダーは呼出し契約、SQLは論理的な保存構造を表す。推論エンジン、OSホスト、配布用アプリの実装は工程表に従って作成・検証する。

合成データに含まれる名前、言語、容量、ハッシュは契約検査用である。モデル資産や実測値の配布は別に管理する。

## 検査

```sh
python -m pip install jsonschema
python specs/validate_specs.py
```

CとC++のコンパイラーがある環境でヘッダーの読込みも検査する。検査の範囲と実装時の受入項目は、付属の検査記録と受入マトリクスに記載する。
