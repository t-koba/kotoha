# ことは 検査記録

設計資料に付属するデータ契約、Appleの対応言語宣言、保存構造と合成データに対して検査を実行した。

## 実行結果

| 検査対象 | 件数 | 結果 |
|---|---:|---|
| JSON Schemaの構造 | 3 | 通過 |
| モデル資産・許諾・言語経路 | 17 | 通過 |
| モードと処理グラフ | 12 | 通過 |
| イベントの順序と整合 | 10 | 通過 |
| 依存の許諾条件 | 32 | 通過 |
| 保存構造・参照・削除 | 14 | 通過 |
| C・C++のヘッダー読込み | 2 | 通過 |
| 機能・契約の対応 | 2 | 通過 |
| Appleの対応言語宣言 | 1 | 通過 |
| 合計 | 93 | 通過 |


検査用データには、構造に適合するケースと、構造・参照・権限・許諾の条件から外れるケースを用意した。後者については、期待する検査箇所で扱いが決まることを確認した。

モデル定義では、ファイル集合、容量、許諾対象、本文ハッシュの参照、方向付き言語経路、必要能力を照合した。実際のモデル資産は利用者の導入領域で管理する設計であり、この検査は合成情報を使用している。

モード定義では、登録済み操作、パラメーター、型、接続、権限、循環を検査した。イベントでは、再送の冪等性、入力スナップショット、順序、確定・終端の扱いを確認した。

保存構造はSQLiteで読み込み、外部キー、資料・参加者の所属、スナップショット、実行単位のイベント、削除時の参照整合を確認した。親ジョブの削除時には別プロジェクトの子ジョブを残し、その親参照を切り離す。ヘッダーはCとC++のコンパイラーで構文検査した。

機能カタログの38項目は受入マトリクスと照合した。本文・ファイル名・スキーマ・宣言・例示データを横断して、名称と契約の整合を確認した。

## 閲覧文書

HTMLの内部参照を照合し、画面幅に応じた表示をブラウザーで確認した。文書の表示資産はファイル内に収めている。

## 実装工程で実施する検査

| 対象 | 検査内容 |
|---|---|
| 推論実装 | モデルのロード、出力、取消、資源解放、パーサーの安全性 |
| プラットフォーム | 入出力、権限、ライフサイクル、アクセシビリティ |
| Linuxホスト | Flutter埋込み、文字入力、表示、OS連携、依存の閉包 |
| 保存実装 | 暗号化、鍵管理、保持期間、変換、復元 |
| 多言語品質 | 言語経路ごとの翻訳、認識、話者処理、表示 |
| 性能 | 用途別の遅延、メモリ、容量、継続負荷、電力 |
| 配布物 | 署名、ソフトウェア部品表、実行時ロード、許諾根拠、通知 |

付属検査の結果は設計契約に関するものであり、上記の実装・実機・配布の検証とは区分して扱う。

## 再実行

```sh
python3 design/specs/validate_specs.py
```

ケースごとの結果は`validation_results.json`に記録する。
