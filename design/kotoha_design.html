ことは 設計書

kotoha／ことは
あらゆる翻訳を、手元で。

ことはは、文字・資料・画像・音声・映像を利用者の端末で扱う、多言語の翻訳環境である。個人で読む・調べる・書く・聞く作業と、人と伝え合う作業を、共通の入力、処理、編集、出力の仕組みで支える。

対象プラットフォームはWindows、macOS、Linux、iOS、iPadOS、Androidとする。本書は製品要求、構造、処理契約、保存、配布、検証を定義する。性能値を設定する際は測定条件と受入基準を組にし、測定結果と設計目標を区別する。

1. 製品の範囲

1.1 作業の基本形

作業は「取り込む → 理解するための処理 → 確認・編集 → 利用する」で構成する。入力と出力は複数を許容する。文章を複数言語へ翻訳する、資料を対照表示しながら読み上げる、映像に字幕を付ける、といった組み合わせを同じ基盤で扱う。

モードは、この組み合わせに表示方法と資源方針を添えたプリセットとする。利用者はプリセットを選び、必要な入力先、訳先、表示、保存を調整できる。利用頻度に応じたピン留め、並べ替え、作業設定の保存を提供する。

2. 多言語と参加者のモデル

2.1 言語を扱う単位

UIの表示言語、入力の言語、区間ごとの推定言語、出力先の言語、参加者が読みたい言語、読み上げ音声の言語をそれぞれ保持する。言語タグはBCP 47を使用し、文字体系、地域、必要な拡張を保持する。[S01]

一つの資料や発話に含まれる複数言語は、資料全体と区間の両方へ記録する。言語推定結果には候補と根拠を添え、利用者が指定・訂正できる。処理に十分な根拠が揃うまで、未確定として扱う。

2.2 言語ごとの能力

能力情報は「どの処理を、どの入出力条件で実行できるか」を表す。翻訳は方向付きの言語経路、OCRは言語・文字体系・縦横配置、音声認識は言語と音響条件、音声合成は言語・音声・出力形式で登録する。複合モデルには、音声から訳文などの直接経路も登録できる。

対応判定は経路の存在と必要条件で行う。入力言語一覧と出力言語一覧の組み合わせは、提供元が保証する方向の情報と合わせて解釈する。表示は「提供元の申告」「評価で確認した条件」「利用者が試す構成」を分ける。

同じ機能に複数の適合経路がある場合は、品質、遅延、メモリ、電力、利用条件、利用者の優先順位で選ぶ。経由言語を使う構成は経路として提示する。

2.3 UIと文字処理

UI文言はメッセージキーとローカライズ資産で管理する。導入済みのUI言語から利用者が選択でき、欠ける文言の表示先も設定で決める。翻訳対象言語の追加とUI文言の追加は独立させる。

Unicodeの書記素、結合文字、双方向表示、縦書き、文字幅、改行、音写を扱う。原資料の文字列と検索・比較用の正規化表現を分ける。フォントの選択は文字範囲と利用許諾で決める。

2.4 参加者と表示先

参加者はID、表示名、希望する読解言語の集合、表示領域、向き、声の照合設定、同意状態を持つ。話者、席、言語、表示先を独立した関係として管理する。

参加者数と表示領域数は画面・操作性・処理能力から決める。対面配置、円卓配置、一覧、個別フォーカスを同じ参加者データで表す。各発話は必要な訳先の集合へ配信し、同じ訳先と生成条件の結果を共有する。

3. UXと作業空間

入口は「翻訳」「取り込む」「会話」「ライブラリ」を基本にする。取り込み対象と利用目的から必要な処理を提案する。利用者の頻用操作をホームに配置できる。

コンパクトな画面は上下・切替表示、広い画面はサイドバーと複数ペインへ適応する。ウィンドウ幅、入力方式、表示倍率、利用中のモードからレイアウトを決定する。

5. UI基盤とLinux統合

5.1 共通UI

Flutterを共通の表示・操作基盤とする。フレームワークはBSD系の許諾で公開され、エンジンとOS埋込み層を分ける構造を持つ。[S02][S03] 採用対象は実際の配布物と推移的依存まで確認して確定する。

Android、iOS、iPadOS、Windows、macOSは、対応するFlutterの埋込み層と自前のOSアダプターを接続する。共通処理はバックグラウンドの実行キューへ割り当て、UIは状態と結果を受け取る。

5.2 Linuxホスト

Flutterの標準Linux構成はGTKを利用し、GTKはLGPLの許諾条件を持つ。[S04][S05] ここを配布方針に整合させるため、LinuxはFlutter Engineの公開埋込みAPIと許諾型のホスト部品を組み合わせる構成とする。埋込みAPIは、ウィンドウツールキットから独立した接続点として公開されている。[S06]

ホストの窓・描画面・入力にはSDLを採用候補とし、アクセシビリティの橋渡しにはAccessKitを評価する。SDLはzlib、AccessKitはMITまたはApacheの許諾で公開されている。[S07][S08] 組込み対象は選択した機能と依存の閉包で決める。

SDLのLinux向け機能には、利用可能なライブラリを実行時にロードする経路がある。[S09] ビルド設定、プラグイン探索、実行時ロードを配布監査へ含める。選択したLinux接続はWayland／X11、入力メソッド、クリップボード、画面倍率、アクセシビリティ、ファイル選択、音声、画面取得を担当する。OSサービスへの接続は監査済みクライアントまたは公開プロトコルを用いる。

このホストは製品側の実装・保守対象になる。文字入力、候補表示、ドラッグ＆ドロップ、複数画面、フォーカス、画面読み上げ、デスクトップ統合を基盤工程の受入項目とし、共通UIの利点と保守費用を同じ評価表で管理する。

5.3 軽量性の評価

UIの選定は配布容量、起動時間、常駐メモリ、表示負荷、操作性、OS統合、保守範囲の総合評価で行う。推論部分はUI契約から独立しているため、表示基盤の改善を局所的に適用できる。

6. エンジン、モデル、能力

6.1 三つの管理単位

エンジン候補にはllama.cpp、whisper.cpp、ONNX Runtime等を含む。これらは処理能力の提供者として接続し、用途に必要な実装だけを配布構成へ含める。[S10][S11][S12]

モデル候補はカタログ情報として扱う。特定モデルの形式、言語数、計算量を製品全体の条件へ広げず、アダプターと能力情報へ収める。PLaMoも対応を評価するモデル群の一つとして登録できる。

6.2 能力の解決

実行計画は、処理要求、導入モデル、エンジン実装、OS機能、利用条件、許可、資源予算を照合して作成する。各候補には成立する条件と評価根拠を添える。

推論経路は、文字認識から翻訳、音声認識から翻訳・合成、複合モデルによる直接処理などを同じ入出力型で比較する。利用者が求める原文確認、時刻、領域、話者情報も経路選択の条件に含める。

6.3 バックエンド

CPU、GPU、その他の演算装置はエンジンごとの実装済み能力として登録する。選択は演算適合、結果の一致、ピークメモリ、継続負荷、遅延、エネルギーの測定で決める。構成と環境の変化に応じて評価結果を再確認する。

7. モデル導入と利用許諾

7.1 配布の境界

アプリの配布物は、実行コード、UI資産、説明、接続定義、必要なライセンス通知で構成する。推論用のモデル資産は、用途と容量にかかわらず利用者が別途導入する。 翻訳、OCR、音声認識、発話検出、話者処理、音声合成、追加学習用データ、モデル固有の語彙・辞書も同じ導入管理へ置く。

モデル導入前でも、設定、モデル選択、資料整理、保存済み対訳の閲覧、手動編集を利用できる。既にOS側へ導入された機能は、提供条件とローカル実行の根拠を確認した能力として接続できる。

7.2 導入フロー

用途・モデルの選択
  → 能力・必要資源・提供元の表示
  → 許諾本文・用途条件・表示義務の確認
  → 同意と必要な利用資格の確認
  → 提供元から取得／手元のファイルを取込み
  → 内容・署名・形式・依存・演算・資源を検査
  → 試験ロード
  → 管理領域へ登録

許諾本文とマニフェストをファイルで取り込めるようにする。同意記録は、対象、本文の内容識別、用途、当事者、日時、必要な追加手続の根拠を持つ。

7.3 マニフェスト

model_manifest.schema.jsonは、モデルID、表示名、提供元、ファイル一覧、内容ハッシュ、サイズ、用途、エンジン能力、アダプター、言語経路、資源条件、許諾情報を定義する。カタログの信頼性、モデル形式の適合性、推論品質の評価はそれぞれ記録する。

検査では署名対象の原バイト列を固定し、署名、長さ、ファイルハッシュ、パス、形式、メタデータ、演算を順に確認する。内容ハッシュは同一性の証拠として扱い、実行の安全性はパーサーの検査と資源制御で支える。

マニフェストはデータとして解釈する。実行可能な処理はアプリが提供する登録済みの実装へ解決する。

7.4 利用者と提供者の責務

モデルの別導入によって配布資産と利用者の選択を分離する。モデル利用時には当該モデルの条件を適用し、アプリ提供者の開発・試験・提供形態についても該当条件を確認する。たとえばPLaMoの許諾には用途・再配布・表示等の条件がある。[S13]

カタログには利用条件の読みやすい要約と原文を併記する。権利処理の単純さはモデル選択の評価項目に含める。モデルや許諾の変更時には、影響する利用条件を提示し、必要な確認を得る。

7.5 保持と切替

モデルは検査済みの不変な内容として管理し、ジョブが使用する内容を固定する。切替先は独立に検査してから有効にし、再実行と比較を可能にする。使用中の資産の削除は参照の解放と同期する。モデル、資料、結果、同意記録はそれぞれの保持規則に従って管理する。

8. 依存ライセンスと配布審査

8.1 採用基準

製品が選択して組み込むコードは、再配布条件を明確に満たせる許諾型ライセンスを採用条件とする。 著作権表示、ライセンス文、必要なNOTICEを配布物から参照できるようにする。

dependency_policy.jsonに採用可能な許諾を定義する。MIT、BSD、Apache、ISC、zlib等を基礎にし、複数許諾は採用する条項を記録する。GPL・AGPL・LGPL系のコードは、この製品依存の採用条件では適合外として判定する。名称だけで一括判定せず、選択したファイル、リンク、機能、再配布単位まで評価する。[S14]

8.2 審査の範囲

8.3 自動化

ビルド時にソフトウェア部品表を生成し、採用条件、選択した許諾、出典、著作権表示、ファイル内容、再配布範囲を照合する。各OSの配布成果物と実行時ロードの観測結果を検査する。配布ゲートは、許諾根拠、通知、モデル資産の別管理、依存の説明が揃った構成を通過条件とする。

配布候補の選定と法的適合の判断は担当を明確にし、判断の根拠を保持する。

9.2 位置と時間

テキストの保存はUTF-8を基本にし、外部契約で用いるオフセットの単位を明示する。UIの書記素位置、内部文字列の位置、元資料の位置は対応表で接続する。

画像は元画像の座標と変換行列、文書は章・ページ・要素、音声・映像は共通タイムラインとサンプル・トラック情報を保持する。原文と訳文の対応は区間の統合・分割も表現できるようにする。

9.3 訂正とイベント整合性

各処理に実行IDを割り当て、イベントはジョブ、実行ID、単調増加の順序、入力スナップショットを持つ。現在の処理と入力に一致するイベントを適用する。原文の訂正時は新たなスナップショットを作り、対象訳文を再確認状態へ移す。

部分結果は置換可能な表示データ、確定結果は記録対象として扱う。終端イベントは一回発行し、保存と表示の双方で冪等に適用する。

9.4 暗号化

保存を選んだ資料と結果は暗号化ストアへ置く。DBにはSQLCipherのコミュニティ配布を候補とし、採用するソース、暗号プロバイダー、通知条件を依存審査へ含める。[S15] 大きなデータは認証付きストリーム暗号のblobとして管理する。[S16]

鍵は利用環境の保護ストアへ格納する。利用可能な保護機能に応じて、パスフレーズからの鍵導出と組み合わせる。検索インデックス、トランザクションログ、一時ファイル、サムネイルまで保存方針を揃える。

一時作業はメモリ内ストアを使い、保存を選んだ時点で永続ストアへ移す。長時間作業の復旧性と一時利用の保持期間は画面上で選択できるようにする。

9.5 互換性と復元

保存形式は、必要な構造と能力の集合で適合を確認する。データ変換は、入力構造の照合、回復用コピー、トランザクション、変換後の照合を経て適用する。既知の変換経路へ解決できたデータを読み書きする。

バックアップには資料・結果・設定・モデルの参照情報を収める。モデル資産は利用者の導入手続で再取得・再選択できる。復元時には鍵、権限、許諾、モデル適合を確認する。

10. 実行契約とライフサイクル

10.1 API

公開境界は固定幅整数、サイズ付き構造体、UTF-8の長さ付きバッファ、不透明ハンドルで定義する。能力照会で必要な契約・入力型・出力型を確認してから、ロードと処理へ進む。

ヘッダーはspecs/kotoha_api.hに定義する。既存契約の意味を保ち、追加能力は名前付き能力と追加の操作契約として導入する。構造体は宣言サイズで読み取る範囲を決め、必要なフィールドと能力の充足を確認する。

10.2 所有権と並行実行

入力は呼出し中の借用と、非同期処理用の所有データを分ける。非同期処理へ渡す内容は呼出し終了までにコピーまたは管理された保持へ移す。出力は呼出元が確保したバッファへ返し、必要な容量を通知する。

エンジンコンテキストは所有する実行キューで直列化する。取消は協調的な要求として扱い、終端と資源利用の終了を確認して解放する。音声の入出力コールバックは固定容量のバッファ操作を担当し、推論・保存は専用キューで行う。

10.3 状態

モデルは候補、同意待ち、取得中、検査中、導入済み、ロード中、利用可能、解放中、削除待ちを持つ。ジョブは準備、待機、実行、一時停止、取消要求、成功、取消、失敗を持つ。終端は結果と復旧情報を確定する。

エラーは原因分類、再試行可否、影響する成果、必要な操作を持つ。利用者が扱える説明と、開発者が検査する診断情報を分ける。

11. 翻訳処理

入力確認、言語と区間の整理、構造の保護、用語・文脈の選択、実行予算の計算、推論、構造復元、意味上の確認支援、結果記録で構成する。

長文は論理的なまとまりを保って分割し、前後の文脈、見出し、表の項目、用語を計算予算内で渡す。入力、指示、文脈、用語、出力予約の合計をトークナイザーで評価する。処理が分割された場合は対応する原文範囲を結果へ添える。

特殊トークンやプロンプト構造はアダプターが生成し、利用者の原文は内容として区別する。出力はまず型付きのテキスト・構造データとして検査し、表示・保存へ渡す。

数値、単位、固有表現、参照、タグ、プレースホルダー等は保持・変換の方針に従って確認する。適用できる文体や用語指定は能力として表示する。逆翻訳・比較は理解の補助として、品質評価の根拠と区別して提供する。

生成キャッシュは原文、言語、文脈、用語、モデル内容、適用契約、生成設定の組で識別する。利用者の編集と承認済み翻訳メモリは生成キャッシュから独立させる。

12. 視覚・文書・構造化資料

12.1 視覚処理

カメラ・画像・画面入力は、向きと座標を正規化し、領域検出、追跡、認識、安定化、翻訳、表示へ流す。表示用映像と認識用の更新頻度を独立させる。追跡中の領域と内容が一致する結果を描画する。

重畳、吹出し、原文併記、訳文一覧、フリーズを用意する。文字列の修正は原画像の位置と紐づけ、変更した区間を再翻訳する。

12.2 資料の中間表現

文書は資料、章、ブロック、インライン要素の中間表現へ変換する。読順、スタイル、表、見出し、脚注、コメント、非表示要素、対象選択を保持する。認識で得た文字も同じ中間表現へ接続する。

12.3 大容量処理

解析、認識、翻訳、整形を段階的に記録し、ページ・ブロック・区間単位で読み込む。表示中の対象を優先する。ジョブの再開には元資料と処理条件の一致を確認する。

一括処理は資料ごとに状態と成果を持つ。利用可能な部分成果、要確認箇所、再処理範囲を一覧で提示する。

13. 音声・映像

13.1 取得と時間管理

入力デバイス、チャネル、サンプルレート、時間基準を記録し、処理能力が要求する形式へ変換する。元の時間と認識・翻訳区間の対応を保つ。マイク、取得可能な再生音声、録音ファイル、映像の音声トラックを共通の音声契約へ接続する。

13.2 逐次処理

発話検出、認識の部分結果、安定区間、訳文、必要な音声出力を段階的に処理する。区切りは音響、言語、文脈、用途に合わせて調整する。直接音声翻訳などの複合経路も、原文確認や時間情報の要求を満たす構成として選択できる。

処理待ち時間、入力時刻からの遅れ、認識・翻訳待ち量を測る。待ち量が増加する場合は更新頻度・計算配分・処理経路を調整し、利用者へ状態を示す。保持予算に応じた一時停止と、保存許可のある入力からの再処理を提供する。

13.3 映像と字幕

映像はコンテナ、コーデック、音声・字幕トラック、時間軸を検査する。対応するOS機能または監査済み処理部品でデコードする。字幕は映像内、別ファイル、認識結果から選択できる。

字幕生成、編集、読みやすい分割、時間調整、原文・訳文の切替を提供する。ファイル出力、同期再生、映像への描画合成はそれぞれの出力能力として選ぶ。使用するコーデックの権利条件も依存審査へ含める。

13.4 合成と音声経路

読み上げは言語、音声、速度、出力先、割込み方針を持つ。出力音声の区間を入力処理へ通知し、エコー制御、入力選択、字幕優先を組み合わせる。出力先切断時は状態と再開方法を表示する。

OS側の音声を使う場合は、導入状態とローカル実行の適合を確認する。アプリ側の合成には利用者が導入した音声モデルを使用する。

14. 会話と話者

話者区間の推定、登録した声との照合、言語推定、音源分離、席の指定は個別の能力として扱う。処理結果には根拠と未確定状態を持たせる。

声の登録は目的、保持期間、利用範囲への同意を得て行う。必要な音響品質が得られた段階で特徴を登録し、保持方針に従って元音声を管理する。照合は会話内の表示振分けを目的とする。

話者の決定は利用者の明示指定を優先し、次に適合する照合結果を用いる。根拠が十分な区間だけ参加者へ割り当て、未割当の区間はその状態を表示する。訂正は関連する表示先・履歴・訳文へ反映する。

各参加者が読む言語に対して字幕を生成する。参加者ごとの表示方向、文字サイズ、原文併記、フォーカスを設定できる。表示人数と同時認識能力は別の資源指標として扱う。

重なった発話は重複区間として記録し、利用可能な分離・再認識・手修正へつなぐ。評価は短い発話、類似する声、距離、騒音、言語の切替、重なり、未登録話者を区分して行う。

15. モード定義と処理グラフ

モード定義は登録済みの処理能力を参照するデータとする。ノードは入出力ポート、必須能力、キュー方針、権限、資源見積りを持つ。定義追加は入出力・表示の組み合わせ、実装追加はアプリの配布工程で扱う。

処理グラフは一回のデータ伝播について有向非巡回として検査する。連続ストリーム、反復、利用者による再翻訳は実行管理のイベントとして繰り返す。分岐、結合、複数訳先、処理スキップを型付き契約で表す。

mode_recipe.schema.jsonの構造検査に加え、ノードの一意性、接続、型、権限、到達可能性、必須能力を検査する。グラフは全体の目的に必要な出力まで到達するものを実行計画へ変換する。

16. 資源・応答性・電力

UI、取得、認識、翻訳、合成、解析、保存の各処理へ共通予算を配分する。予算はメモリ、アクセラレーター領域、スレッド、待ちキュー、I/O、期限を含む。

モデルは必要な作業に合わせて読み込み、連続利用の見込みと資源状態に応じて保持する。解放は再ロード費用と比較して決める。キャッシュとメモリマッピングは、コピー量とピーク使用量を測定して適用する。

リアルタイムの取得は計算と分離し、期限付きの認識・翻訳、利用者の明示操作、表示中の資料、まとめ処理へ優先度を配分する。待機時間も加味して処理機会を調整する。

性能設定は応答性、品質、電力の優先順位を表す。モデル変更や処理経路の変更に伴う品質差を提示し、利用者の選択範囲内で適応する。

17. セキュリティとC++

17.1 安全性の契約

C++ではRAIIと所有権型、長さ付きデータ、検査済み演算、資源上限を基本にする。借用範囲と寿命をレビュー可能な形で示し、コンテキストごとの実行順序を固定する。外部境界は例外を契約エラーへ変換する。[S17]

文書、画像、音声、モデル、マニフェストは検査対象の入力として扱う。寸法、展開量、階層、要素数、メタデータ、処理時間を資源予算と照合する。大きな正当データは分割・逐次処理へ導く。

解析内容はデータとして処理する。実行権限はアプリが配布・検査する登録済み処理へ与える。モデルの特殊トークンや文書の能動要素は、内容と制御の境界を通して扱う。

17.2 隔離と復旧

環境が提供するプロセス・権限分離を活用し、処理workerへ必要な読取専用資産と出力領域を渡す。IPCは相手、メッセージ長、資源、所有権を検証する。同一プロセス内の処理は、監査・入力検査・実行順序・資源上限を中心に保護する。

障害復旧は確定済みの保存点と再実行計画で行う。隔離の強度と適用範囲をOS能力として記録する。

17.3 検査

静的解析、コンパイラ警告、メモリ・未定義動作・競合の検査、ファジング、取消と解放の競合試験を組み合わせる。[S18] モデル解析、アーカイブ展開、画像寸法、文字列境界、イベント順序、資源枯渇を重点対象とする。

依存の由来、既知の脆弱性、配布署名、ロード時の内容確認を供給網の検査へ含める。

18. プライバシーと通信

認識、解析、翻訳、話者処理、合成は利用端末の処理領域で実行する。処理用workerに与える権限は、必要な入力と出力に対応させる。

通信は取得・明示的な転送を担当する部品へ集約し、目的、接続先、対象データ、期限、利用者の許可を持つ操作として実施する。通信停止設定ではローカルファイルの取込みと端末内処理を利用できる。

アプリが管理するデータの経路と、外部のファイル提供者・入力手段・OSサービスが管理する経路を区別して表示する。通信試験はアプリ本体、同梱部品、選択したOS連携の範囲を明示して行う。

カメラ、マイク、画面、ファイルの権限は用途と期間に対応させる。利用中の取得状態、保存範囲、参加者の同意、停止方法を表示する。生の音声・映像、話者特徴、原文・訳文には個別の保持方針を適用する。

診断は処理種別、状態、資源、時間、原因分類を中心とする。利用者が内容を確認してから、選択した診断情報を出力できる。

19. OS連携と自動化

OSが提供する共有、ファイル選択、カメラ、音声、画面取得、鍵保護、背景処理を能力として公開する。実行経路は利用可能な権限とライフサイクルに合わせて選ぶ。

共有拡張とブラウザ連携は、利用者が選んだ内容と権限を作業キューへ渡す。拡張と本体の寿命を分け、暗号化された受渡し領域と再開操作を用意する。

フォルダー監視は対象、再帰、除外、ファイル安定条件、出力先、キュー予算を設定する。CLIはGUIと同じ能力解決、モデル管理、実行契約、許諾状態を利用する。

kotoha subtitle --input <path> --target-language <tag> --output <path>

kotoha models import --manifest <path>

標準出力は成果、標準エラーは進捗・診断に使う。終了コードは成功、入力、能力、許諾、資源、取消、処理障害を区別する。自動化からの同意は、確認対象の許諾内容と適用範囲を明示して記録する。

20. 配布、更新、互換性

配布物はOSとアーキテクチャごとに再現可能な手順で生成し、署名、依存情報、通知、利用可能な能力を添える。アプリの実行コードとモデル資産を別の管理経路で扱う。Appleの配布条件には実行コードの取得に関する規定があり、この区分を配布審査でも確認する。[S19]

互換性は必要な能力、構造、操作契約で照合する。アプリの更新はコードと既存データの適合を確認し、回復手段を確保して適用する。モデルの切替は同意・内容・能力・進行中ジョブへの影響を確認して行う。

依存部品は内容と取得元を固定して再現性を持たせ、変更時に関連する機能・品質・許諾・安全性を再検査する。プラットフォームが配布管理に要求するメタデータは配布基盤が管理する。

21. 品質と受入

21.1 機能受入

各機能について、通常利用、編集、取消、権限変更、導入状態、資源不足、入力の問題、処理中断、再開、出力、アクセシビリティを確認する。適用条件は能力表と一致させる。

21.2 多言語品質

評価は言語方向、文字体系、領域、文章長、音響・画像品質、文体、混在言語で層別化する。評価対象は利用可能な能力と利用状況に基づいて選び、各言語経路へ同じ評価手続きを適用する。

翻訳は意味保持、抜け・追加、重大な意味変化、数値・固有表現、流暢さを測る。音声・文字認識は適切な区間・語・文字単位を選び、話者処理は誤割当と判定できた割合を併記する。測定条件、標本、評価者の適性、指標、信頼区間を記録する。

21.3 構造・安全・復旧

入力と出力の構造、原資料の保持、編集の優先、同意の範囲、イベントの整合、暗号化、通信、資源解放を検査する。停止・強制終了・容量変化・権限変更を各処理段階へ注入して復旧を確認する。

21.4 配布受入

機能と能力表、UI資産、プラットフォーム統合、モデルの導入・削除、依存許諾、通知、署名、保存形式の適合、サポート情報を配布物単位で照合する。基盤として採用するLinuxホストも同じ機能・文字入力・アクセシビリティ基準で受け入れる。

構造と意味の検査

JSON Schemaはフィールドと型を扱う。ファイルの参照、許諾の対象、言語経路、グラフの接続、イベントの順序は意味検査で確認する。例示データは検査用の合成情報である。

スキーマの$schemaは使用する外部標準を示す。契約の適合は必要能力と構造の一致で確認する。

モデルの検査

署名付きカタログと持込みファイルは、由来を別に記録する。署名の検証では署名対象の原バイト列を使用し、その後にJSONを解析する。モデル資産は整合性、形式、演算、資源を検査する。

言語タグの正規化と登録情報の照合は言語アダプターが担当する。付属検査はフィールドの構文と参照整合を扱う。個別言語の翻訳品質は評価プロファイルで測定する。

モードの実行

操作レジストリには各操作の入力・出力型、必須能力、必要権限、パラメーター契約を登録する。モードはそのレジストリへ解決する。新しい処理実装は配布工程、処理の組み合わせはモード定義として管理する。

ノードはsource、processor、sinkの役割を持つ。入力ポートは宣言された型と接続数へ適合し、全ノードが入力から出力へ至る経路に属する。反復実行とストリームの継続はジョブ管理が担当する。

イベントと保存

イベントはjob_id、run_id、sequence、kind、payloadで識別する。部分結果、確定結果、訂正結果を区別する。input_snapshotは保存側のsegment_snapshots.snapshot_idに対応し、現在の処理対象との一致を実行時に確認する。

同一イベントの再送は冪等に適用し、同じ順序位置に異なる内容が到着した場合は整合性エラーとして扱う。終端イベントを確定し、確定結果を安全に受け渡してから資源を解放する。保留キューは設定した予算でバックプレッシャーをかける。

SQLは暗号化ストレージに適用する論理構造を定義する。付属検査はSQLiteによる構文と参照の検査であり、暗号化・鍵管理・実行時の権限はストレージ実装の試験対象とする。

C ABI

各構造体のstruct_sizeと必要能力を確認して呼び出す。入力の借用は呼出し中、非同期入力はエンジンが所有するコピーとして扱う。出力は呼出元のバッファへ格納する。容量不足時は必要なバイト数を返し、イベントを受信待ちに保持する。

同一エンジンへの呼出しは所有キューで順序付けする。取消はハンドルの有効期間中に行い、終端とキュー排出を確認して解放する。解放と呼出しは所有者が同期する。

Pythonとjsonschemaを使用する。ヘッダーの読込み検査にはCとC++のコンパイラーを使用する。

python -m pip install jsonschema
python specs/validate_specs.py

#!/usr/bin/env python3
"""Validate kotoha's design contracts with synthetic fixtures."""
from __future__ import annotations

except ImportError as exc:
    raise SystemExit("Install the inspection dependency: python -m pip install jsonschema") from exc

ROOT = Path(__file__).resolve().parents[1]
RESULTS: list[dict[str, str]] = []


def load(path: str) -> Any:
    return json.loads((ROOT / path).read_text(encoding="utf-8"))


def require(condition: bool, detail: str) -> None:
    if not condition:
        raise ValueError(detail)


def check(name: str, action: Callable[[], Any], rejected: bool = False) -> None:
    try:
        action()
    except (ValueError, ValidationError, sqlite3.IntegrityError) as exc:
        if rejected:
            RESULTS.append({"name": name, "status": "pass", "case": "incompatible"})
            return
        raise RuntimeError(f"{name}: {exc}") from exc
    if rejected:
        raise RuntimeError(f"{name}: incompatible input was accepted")
    RESULTS.append({"name": name, "status": "pass", "case": "compatible"})


SCHEMAS = {name: load(f"specs/{name}.schema.json")
           for name in ("model_manifest", "mode_recipe", "engine_event")}


def structural(name: str, data: Any) -> None:
    Draft202012Validator(SCHEMAS[name]).validate(data)


def safe_path(value: str) -> str:
    require(bool(value) and not value.startswith(("/", "\\")), "relative path required")
    require(not re.match(r"^[A-Za-z]:", value), "drive path")
    require(not any(ord(c) < 32 or c in '\\<>:"|?*' for c in value), "path characters")
    parts = value.split("/")
    reserved = {"con", "prn", "aux", "nul", *(f"com{i}" for i in range(1, 10)), *(f"lpt{i}" for i in range(1, 10))}
    for part in parts:
        require(part not in ("", ".", "..") and not part.endswith((".", " ")), "path component")
        require(part.split(".")[0].casefold() not in reserved, "reserved path component")
    return unicodedata.normalize("NFC", value).casefold()


def validate_model(data: dict[str, Any]) -> None:
    structural("model_manifest", data)
    files = data["files"]
    keys = [safe_path(x["path"]) for x in files]
    require(len(keys) == len(set(keys)), "duplicate asset path")
    by_path = {x["path"]: x for x in files}
    require(sum(x["size_bytes"] for x in files) == data["resources"]["storage_bytes"], "storage total")
    coverage: set[str] = set()
    terms_ids: set[str] = set()
    for term in data["terms"]:
        require(term["id"] not in terms_ids, "duplicate terms")
        terms_ids.add(term["id"])
        asset = by_path.get(term["text_file"])
        require(asset is not None and asset["role"] == "terms", "terms file reference")
        require(asset["sha256"] == term["text_sha256"], "terms digest")
        require(set(term["covered_files"]) <= set(by_path), "terms coverage reference")
        coverage.update(term["covered_files"])
    require(coverage == set(by_path), "asset terms coverage")
    seen_caps: set[str] = set()
    required = set(data["executor"]["required_capabilities"])
    for task in data["tasks"]:
        cap = task["capability"]
        require(cap not in seen_caps, "duplicate task capability")
        require(cap in required, "task capability missing from executor")
        seen_caps.add(cap)
        langs = task["languages"]
        for side in ("source", "target"):
            tags = [x.casefold() for x in langs[side]]
            require(len(tags) == len(set(tags)), "duplicate language tag")
        pairs = set()
        for route in langs["routes"]:
            source, target = route["source"].casefold(), route["target"].casefold()
            require(source in {x.casefold() for x in langs["source"]}, "route source")
            require(target in {x.casefold() for x in langs["target"]}, "route target")
            require((source, target) not in pairs, "duplicate language route")
            pairs.add((source, target))
            if route["evidence"] == "evaluation":
                require(bool(route.get("evidence_ref")), "evaluation reference")
        if cap.startswith("translation."):

def validate_recipe(data: dict[str, Any], registry: dict[str, Any]) -> None:
    structural("mode_recipe", data)
    nodes = {n["id"]: n for n in data["nodes"]}
    require(len(nodes) == len(data["nodes"]), "duplicate node")
    required_permissions: set[str] = set()
    for node in nodes.values():
        entry = registry.get(node["operation"])
        require(entry is not None, "operation registration")
        for field in ("role", "inputs", "outputs"):
            require(node[field] == entry[field], f"registered {field}")
        require(set(node["required_capabilities"]) == set(entry["required_capabilities"]), "required capability contract")
        Draft202012Validator(entry["parameters_schema"]).validate(node["parameters"])
        required_permissions.update(entry["permissions"])
    require(set(data["permissions"]) == required_permissions, "permission scope")
    incoming: dict[tuple[str, str], int] = defaultdict(int)
    out: dict[str, list[str]] = defaultdict(list)
    reverse: dict[str, list[str]] = defaultdict(list)
    indegree = {k: 0 for k in nodes}
    for edge in data["edges"]:
        a, b = edge["from_node"], edge["to_node"]
        require(a in nodes and b in nodes, "edge endpoint")
        left = nodes[a]["outputs"].get(edge["from_port"])
        right = nodes[b]["inputs"].get(edge["to_port"])
        require(left is not None and right is not None and left == right, "port types")
        incoming[(b, edge["to_port"])] += 1
        require(incoming[(b, edge["to_port"])] == 1, "input cardinality")
        out[a].append(b)
        reverse[b].append(a)
        indegree[b] += 1
    for key, node in nodes.items():
        for port in node["inputs"]:
            require(incoming[(key, port)] == 1, "required input")
    queue = deque(k for k, d in indegree.items() if d == 0)
    processed = []
    while queue:
        key = queue.popleft()
        processed.append(key)
        for nxt in out[key]:
            indegree[nxt] -= 1
            if indegree[nxt] == 0:
                queue.append(nxt)
    require(len(processed) == len(nodes), "graph cycle")
    sources = {key for key, n in nodes.items() if n["role"] == "source"}
    sinks = {key for key, n in nodes.items() if n["role"] == "sink"}
    require(bool(sources) and bool(sinks), "source and sink")
    def reach(start: set[str], edges: dict[str, list[str]]) -> set[str]:
        found = set(start)
        pending = list(start)
        while pending:
            for nxt in edges[pending.pop()]:
                if nxt not in found:
                    found.add(nxt)
                    pending.append(nxt)
        return found
    require(reach(sources, out) == set(nodes), "reachable from source")
    require(reach(sinks, reverse) == set(nodes), "can reach output")


def validate_events(events: list[dict[str, Any]], expected_snapshots: dict[str, str] | None = None) -> None:
    states: dict[tuple[str, str], dict[str, Any]] = {}
    seen: dict[tuple[str, str, int], str] = {}
    for event in events:
        structural("engine_event", event)
        run = (event["job_id"], event["run_id"])
        key = (*run, event["sequence"])
        content = json.dumps(event, sort_keys=True, ensure_ascii=False)
        if key in seen:
            require(seen[key] == content, "event collision")
            continue
        state = states.setdefault(run, {"last": -1, "terminal": False, "committed": set()})
        require(not state["terminal"], "event after terminal")
        require(event["sequence"] > state["last"], "event order")
        payload = event["payload"]
        if event["kind"].startswith("segment."):
            segment = payload["segment_id"]
            if expected_snapshots is not None:
                require(expected_snapshots.get(segment) == payload["input_snapshot"], "current input snapshot")
            point = (segment, payload["input_snapshot"])
            if event["kind"] == "segment.partial":
                require(point not in state["committed"], "partial after commit")
            else:
                state["committed"].add(point)
        if event["kind"] == "job.progress":
            require(payload["processed"] <= payload["total"], "progress bound")
        if event["kind"] == "job.terminal":
            state["terminal"] = True
        state["last"] = event["sequence"]
        seen[key] = content
    require(bool(states) and all(s["terminal"] for s in states.values()), "terminal per run")


def license_terms(expression: str, allowed: set[str]) -> set[str] | None:
    tokens = re.findall(r"\(|\)|[A-Za-z0-9.+-]+", expression)
    require("".join(tokens) == re.sub(r"\s+", "", expression), "license expression characters")
    pos = 0
    def atom() -> Any:
        nonlocal pos
        require(pos < len(tokens), "license expression operand")
        token = tokens[pos]
        pos += 1
        if token == "(":
            value = disjunction()
            require(pos < len(tokens) and tokens[pos] == ")", "license expression group")
            pos += 1
            return value
        require(token not in {"AND", "OR", "WITH", ")"}, "license identifier")
        if pos < len(tokens) and tokens[pos] == "WITH":
            pos += 1
            require(pos < len(tokens) and tokens[pos] not in {"AND", "OR", "WITH", "(", ")"}, "exception identifier")
            token += " WITH " + tokens[pos]
            pos += 1
        return ("license", token)
    def conjunction() -> Any:
        nonlocal pos
        value = atom()
        while pos < len(tokens) and tokens[pos] == "AND":
            pos += 1
            value = ("and", value, atom())
        return value
    def disjunction() -> Any:
        nonlocal pos
        value = conjunction()
        while pos < len(tokens) and tokens[pos] == "OR":
            pos += 1
            value = ("or", value, conjunction())
        return value
    tree = disjunction()
    require(pos == len(tokens), "license expression trailing token")
    def evaluate(node: Any) -> set[str] | None:
        if node[0] == "license":
            return {node[1]} if node[1] in allowed else None
        left, right = evaluate(node[1]), evaluate(node[2])
        if node[0] == "and":
            return left | right if left is not None and right is not None else None
        return left if left is not None else right
    return evaluate(tree)
